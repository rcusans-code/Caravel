# Decisions locked before coding

Weak spots from the project brief, turned into day-zero decisions. Changing these at 02:00 costs hours. Propose changes in the team chat, then edit this file.

| # | Decision | Why |
|---|---|---|
| 1 | **Real Circle testnet USDC** via its SAC. Mock USDC only if the faucet fails by 13:00. | Real infra lifts Composed track alignment (20% of score). |
| 2 | **Strict SEP-40 oracle.** Mock implements the full trait (`base`, `assets`, `decimals`, `resolution`, `price`, `prices`, `lastprice`). Same client also reads one live Reflector/RedStone testnet feed. | Proves swapping to RedStone/Chainlink is config-only. |
| 3 | **Fee comes out of interest.** `fee = interest × fee_bps`; lender gets `principal + interest − fee`; then borrower surplus. | Lender must never receive more than the offer terms. |
| 4 | **Explicit shortfall path.** If liquidation proceeds < debt: lender takes all proceeds, borrower 0, emit `Shortfall { repo_id, amount }`. | Buffer is only ~1% (3% haircut vs 2% liquidator discount). Say it before a judge does. |
| 5 | **Time compression via config only.** `term_secs`, `margin_window_secs`, `grace_secs`, `max_nav_age_secs`. Demo profile: 1 day = 60 s, 7-day term = 7 min, margin window 120 s, grace 60 s, NAV age 180 s. | No demo hacks in contract logic. |
| 6 | **Stale NAV** blocks `take_offer` and `liquidate`. Never blocks `repay` or `top_up`. | A borrower can always exit. |
| 7 | **Access:** `check_margin`, `default` callable by anyone (keeper-friendly). `liquidate` whitelisted only. Borrower auth on `take_offer`; lender auth at `create_offer` when USDC is escrowed. | Clear trust model. |
| 8 | **Units:** i128, 7-decimal Stellar units; NAV scaled by oracle `decimals()`. Interest rounds up (lender's favour), LTV rounds down. One `math.rs` with tests. | Avoid off-by-decimals bugs at 03:00. |
| 9 | **AUTH_REQUIRED fallback.** Spike by 13:00. If a contract address can't be authorized, keep the flag for wallets where possible; worst case issue tBENJI without it and enforce the whitelist in-contract, flagged in README as a testnet workaround. | Unlocked track depends on native compliance. |
| 10 | **Target user is active, not passive.** Repo rate above fund yield = negative carry for passive holders. Pitch to traders/MMs whose USDC earns more than the repo costs. | Pre-empt the obvious economics question. |
| 11 | **Commit history starts today.** Small, frequent commits; README "Built during HackMeridian" section. | Hackathon Progress is 10% and judges check git log. |
| 12 | **Smart wallet only after G3 is green.** Freighter first; passkey login (OpenZeppelin smart accounts / Stellar Passport) only if the happy path works on testnet by 00:00. | Stated priority, but not at the cost of the core demo. |
| 13 | **Haircut is per asset, in contract config.** `AssetConfig { oracle_asset, haircut_bps, enabled, max_nav_age_secs }` (staleness per asset since #25), admin-updatable without redeploy. Offers name the collateral asset but carry no haircut; the UI shows the asset's haircut. Tier numbers tuned later (proposal: docs/collateral-research.md §3). | Agile: re-tier an asset in one call; lenders can't undercut the floor. |
| 14 | **Margin trigger** = `debt > collateral × NAV × (1 − liq_discount_bps)`. At the trigger a liquidation still pays the lender in full. Initial LTV check uses the asset haircut (`debt ≤ value × (1 − haircut_bps)`). Both bps are config; numbers tuned later. | Without a separate trigger, any NAV tick after a max-LTV take fires a margin call. |
| 15 | **Debt = principal + full-term interest**, fixed at `take_offer`. Early repay pays the same amount; no pro-rata. | Repo convention; one number for lender, borrower and margin math. |
| 16 | **Full takes only.** Borrower receives the whole offer principal and posts `collateral = debt / (NAV × (1 − haircut))`, rounded up. | No partial-fill state in `Offer`. |
| 17 | **Stale NAV also blocks `check_margin`** (extends decision 6). `default` on maturity + grace needs no NAV. | No margin call on an old price. |
| 18 | **Haircut strictly above liquidation discount.** `set_asset` rejects unless `liquidation_discount_bps < haircut_bps < 10_000` (`InvalidConfig`). | A take at max LTV then opens strictly below the margin trigger (#14). |
| 19 | **Haircut is snapshotted on the repo at take.** `Repo.haircut_bps` is fixed; re-tiering an asset (#13) only affects new takes. `RepoOpened` carries it. | Admin changes never move a live borrower's terms. |
| 20 | **Top-up clears a margin call only at initial margin**: once `ltv_ok(debt, collateral, nav, repo.haircut_bps)` holds. The minimum to leave breach (`required_collateral` at the liquidation discount) is shown for info only. | TradFi convention; avoids a repo flapping in and out of margin call at the trigger. |
| 21 | **`take_offer` computes the collateral, no amount argument** (#16): `required_collateral(debt, nav, dec, haircut)`, rounded up. The borrower's auth on the SAC transfer pins the exact amount. | If NAV moves between simulate and submit, the tx fails instead of overcharging. |
| 22 | **Asset configs live in instance storage**, keyed by token address, with a SEP-40 `Asset` (`Stellar(Address)` / `Other(Symbol)`) for the oracle. Missing or disabled asset → `AssetNotSupported` on `create_offer`; live repos unaffected. | Few assets, shared instance TTL; same asset shape as Reflector so the mock and live feeds accept it. |
| 23 | **`take_offer` re-checks the asset.** An offer whose collateral asset was disabled (or removed) after `create_offer` cannot be taken: `AssetNotSupported`. The lender can still `cancel_offer`; live repos are unaffected (#22). | Admin stops new risk on an asset in one call, including offers already on the board. |
| 24 | **Compliance-agnostic core.** The repo contract moves collateral only through the SEP-41 `token::Client` (`transfer` with the payer's auth; no `approve` / `transfer_from`, no SAC admin calls). Who may hold a token stays the issuer's call: BENJI admits the contract and liquidators with authorized trustlines (AUTH_REQUIRED), Spiko with its own Soroban permission-manager / smart-account contracts. No issuer-specific compliance code in the core; `test_allowlist.rs` proves it with a custom allowlist token. | Spiko, the largest RWA issuer on Stellar, does not rely only on classic authorized trustlines. One code path serves every issuer. |
| 25 | **NAV staleness is per asset.** `AssetConfig.max_nav_age_secs` replaces `Config.max_nav_age_secs` (`set_asset` rejects 0 with `InvalidConfig`). Production ≈ 96h (345,600 s) so a NAV published Friday still covers the weekend; demo 180 s. Stale NAV blocks `take_offer` and `check_margin`. It never blocks `repay` or `top_up`. Snapshot nothing on the repo; the live asset value applies. | A 26h window breaks every weekend: on Saturday nobody could open a repo or check margin. Funds publish on business days. |
| 26 | **Launch haircuts (7-day term):** USTBL, BENJI, USDY 3%; EUTBL ≈5% (EUR/USD against a USDC loan); CETES 8–10%; SAFO and other swap-based funds only after due diligence (not enabled). All above the 2% liquidation discount (#18). Demo runs tBENJI at 3%. | Replaces the open tier proposal in collateral-research.md §3. |
| 27 | **Auto-repay, opt-in per repo, on by default in the app.** `take_offer(.., auto_repay)` or `set_auto_repay` signs a USDC (SAC) allowance to the contract for the debt. From maturity (or a missed margin deadline) anyone can call `auto_repay`, and `default` tries it first, so an opted-in borrower who holds the USDC ends `Repaid`, never `Defaulted`. One `transfer_from` pulls the whole debt into the contract; if it fails nothing moves and the repo defaults as before. `Repaid.automatic` marks it. The allowance is on the USDC cash leg only; collateral still moves by `transfer` alone, so #24 holds for every collateral token. | A solvent borrower who forgot to press Repay lost the liquidation discount on the whole collateral (testnet Repo #4, 25 Oct 2026). |
| 28 | **Collateral amounts are in the token's own decimals.** The contract reads the collateral token's `decimals()` and folds it into the NAV scale (`oracle::scale_for_token`: `dec = nav_decimals + token_decimals − 7`), so `math.rs` still works in 7-decimal USDC. tBENJI (7) is unchanged; Spiko tokens are 5 (mainnet eurSAFO `decimals()` = 5). Refines #8. | Without it a 5-decimal token is valued 100× too low, so the borrower would post 100× the collateral. Held by `test_spiko::collateral_is_in_token_units`. |
| 29 | **tSAFO is the testnet collateral #2 (issue #20).** USD `SAFO` only: eurSAFO needs a EUR/USD feed. Testnet stand-in `contracts/spiko-mock`: allowlist on every transfer, no `approve` / `transfer_from`, issuer pause. Testnet only, `haircut_bps` 3000 by default, admin-updatable (#13); production SAFO stays disabled until due diligence (#26), so tSAFO demonstrates the permissioned-token path of #24, not a launch listing. Production needs Spiko to allowlist the Caravel contract **and every liquidator**, and a signed NAV or an oracle that covers it. | The borrower's auth on `take_offer` covers the transfer, so no allowance is needed (tested). SAFO's risk assets sit behind a bank swap, hence the Tier 5 haircut. |
| 30 | **Separate pause switches per asset (issue #28).** `set_pause(asset, Pause { no_new_repos, no_seize })`, admin only for now. `no_new_repos` blocks `create_offer` and `take_offer` (`Paused`); `AssetConfig.enabled = false` stays as its alias (`AssetNotSupported`). `no_seize` blocks `default` and `liquidate` (`Paused`). `repay`, `top_up`, `cancel_offer` and auto-repay have no switch. Under `no_seize` the default clock keeps running and is not extended: an overdue repo stays `Open` / `MarginCall`, so the borrower can still repay or top up, and once the switch clears anyone can default it at once. Stored apart from `AssetConfig`, so `set_asset` never clears a pause. Guardian with instant set and timelocked clear: guardian issue. | Stopping one action never traps users in another: an issuer pause or a suspect in-band NAV halts seizure without blocking exits. |
