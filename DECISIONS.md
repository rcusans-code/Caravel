# Decisions locked before coding

| 1 | **Real Circle testnet USDC** via its SAC. Mock USDC only if the faucet fails by 13:00. | Real infra lifts Composed track alignment (20% of score). |
| 2 | **Strict SEP-40 oracle.** Mock implements the full trait (`base`, `assets`, `decimals`, `resolution`, `price`, `prices`, `lastprice`). Same client also reads one live Reflector/RedStone testnet feed. | Proves swapping to RedStone/Chainlink is config-only. |
| 3 | **Fee comes out of interest.** `fee = interest × fee_bps`; lender gets `principal + interest − fee`; then borrower surplus. | Lender must never receive more than the offer terms. |
| 4 | **Explicit shortfall path.** If liquidation proceeds < debt: lender takes all proceeds, borrower 0, emit `Shortfall { repo_id, amount }`. | Buffer is only ~2% (3% haircut vs 1% liquidator discount, #35; ~1% at the original 2%). Say it before a judge does. |
| 5 | **Time compression via config only.** `term_secs`, `margin_window_secs`, `grace_secs`, `max_nav_age_secs`. Demo profile: 1 day = 60 s, 7-day term = 7 min, margin window 120 s, grace 60 s, NAV age 180 s. | No demo hacks in contract logic. |
| 6 | **Stale NAV** blocks `take_offer` and `liquidate`. Never blocks `repay` or `top_up`. | A borrower can always exit. |
| 7 | **Access:** `check_margin`, `default` callable by anyone (keeper-friendly). `liquidate` whitelisted only. Borrower auth on `take_offer`; lender auth at `create_offer` when USDC is escrowed. | Clear trust model. |

| 13 | **Haircut is per asset, in contract config.** `AssetConfig { oracle_asset, haircut_bps, enabled, max_nav_age_secs, max_nav_move_bps, nav_floor, nav_ceiling, max_open_debt }` (staleness per asset since #25, NAV band since #31, exposure cap since #32), admin-updatable without redeploy. Tier numbers tuned later (proposal: docs/collateral-research.md §3). | Agile: re-tier an asset in one call; lenders can't undercut the floor. |
| 14 | **Margin trigger** = `debt > collateral × NAV × (1 − liq_discount_bps)`. At the trigger a liquidation still pays the lender in full. Initial LTV check uses the asset haircut (`debt ≤ value × (1 − haircut_bps)`). Both bps are config; numbers tuned later. | Without a separate trigger, any NAV tick after a max-LTV take fires a margin call. |
| 15 | **Debt = principal + full-term interest**, fixed at `take_offer`. Early repay pays the same amount; no pro-rata. | Repo convention; one number for lender, borrower and margin math. |
| 16 | **Full takes only.** Borrower receives the whole offer principal and posts `collateral = debt / (NAV × (1 − haircut))`, rounded up. | No partial-fill state in `Offer`. |
| 17 | **Stale NAV also blocks `check_margin`** (extends decision 6). `default` on maturity + grace needs no NAV. | No margin call on an old price. |
| 18 | **Haircut strictly above liquidation discount.** `set_asset` rejects unless `liquidation_discount_bps < haircut_bps < 10_000` (`InvalidConfig`). | A take at max LTV then opens strictly below the margin trigger (#14). |
| 19 | **Haircut is snapshotted on the repo at take.** `Repo.haircut_bps` is fixed; re-tiering an asset (#13) only affects new takes. `RepoOpened` carries it. | Admin changes never move a live borrower's terms. |
| 20 | **A margin call clears by top-up at initial margin, or by NAV recovery at the trigger.** A top-up clears it once `ltv_ok(debt, collateral, nav, repo.haircut_bps)` holds (last known NAV). If the deadline passes, `default` first re-checks breach at a fresh, in-band NAV; if the loan is no longer past the asset's margin trigger (`margin_breached`, the `check_margin` test), the repo returns to Open (deadline cleared, `MarginCleared` event). With no price, a stale NAV or one outside the sanity band (#31), `default` returns `NoPrice` / `StaleNav` / `NavOutOfBand` and waits; a missed call defaults only on a fresh, in-band NAV that confirms the breach. The maturity path is unchanged and never reads the NAV. | An active borrower cures to initial margin (TradFi convention, no flapping at the trigger). A corrected bad price push no longer costs an absent borrower the liquidation discount (flash-crash S2b/S3a). |
| 21 | **`take_offer` computes the collateral, no amount argument** (#16): `required_collateral(debt, nav, dec, haircut)`, rounded up. The borrower's auth on the SAC transfer pins the exact amount. | If NAV moves between simulate and submit, the tx fails instead of overcharging. |
| 22 | **Asset configs live in instance storage**, keyed by token address, with a SEP-40 `Asset` (`Stellar(Address)` / `Other(Symbol)`) for the oracle. | 27 | **Auto-repay, opt-in per repo, on by default in the app.** `take_offer(.., auto_repay)` or `set_auto_repay` signs a USDC (SAC) allowance to the contract for the debt. From maturity (or a missed margin deadline) anyone can call `auto_repay`, and `default` tries it first, so an opted-in borrower who holds the USDC ends `Repaid`, never `Defaulted`. One `transfer_from` pulls the whole debt into the contract; if it fails nothing moves and the repo defaults as before. `Repaid.automatic` marks it. The allowance is on the USDC cash leg only; collateral still moves by `transfer` alone, so #24 holds for every collateral token. | A solvent borrower who forgot to press Repay lost the liquidation discount on the whole collateral (testnet Repo #4, 25 Oct 2026). |
| 28 | **Collateral amounts are in the token's own decimals.** The contract reads the collateral token's `decimals()` and folds it into the NAV scale (`oracle::scale_for_token`: `dec = nav_decimals + token_decimals − 7`), so `math.rs` still works in 7-decimal USDC. tBENJI (7) is unchanged; Spiko tokens are 5 (mainnet eurSAFO `decimals()` = 5). | 29 | **tSAFO is the testnet collateral #2 (issue #20).** USD `SAFO` only: eurSAFO needs a EUR/USD feed. | 30 | **Separate pause switches per asset (issue #28).** `set_pause(asset, Pause { no_new_repos, no_seize })`, admin only for now. `no_new_repos` blocks `create_offer` and `take_offer` (`Paused`); `AssetConfig.enabled = false` stays as its alias (`AssetNotSupported`). `no_seize` blocks `default` and `liquidate` (`Paused`). `repay`, `top_up`, `cancel_offer` and auto-repay have no switch. Under `no_seize` the default clock keeps running and is not extended: an overdue repo stays `Open` / `MarginCall`, so the borrower can still repay or top up, and once the switch clears anyone can default it at once. Stored apart from `AssetConfig`, so `set_asset` never clears a pause. Switching on is instant for admin and guardian; clearing goes through the timelock (#33). | Stopping one action never traps users in another: an issuer pause or a suspect in-band NAV halts seizure without blocking exits. |
| 31 | **NAV sanity band, per asset (issue #26).** `AssetConfig.max_nav_move_bps` (> 0) and optional `nav_floor` / `nav_ceiling` (feed scale, inclusive, > 0, floor ≤ ceiling; else `InvalidConfig`). The latest NAV must be within `max_nav_move_bps` of **every** positive record in the feed's last 20 (`prices(asset, 20)`, read-only) and inside the bounds, else `NavOutOfBand`. Blocks `take_offer`, `check_margin` and `liquidate`, the same set as stale NAV (checked after staleness). Never blocks `repay` or `top_up`; an out-of-band NAV only stops `top_up` from clearing a margin call. With one record (no history) only the bounds apply. A price is accepted once the whole window agrees with it (20 records, ~20 min at nav-keeper's 60 s re-post), or when the admin widens the band, which since #33 waits out the timelock (`propose_asset` → `execute_asset`): that is the recovery path for a real move and for a correction after a bad push. Narrowing the band stays instant. **Launch values** (EUTBL and CETES superseded by #35: 500 and 800): BENJI, USTBL, USDY 50 bps; BENJI also floor 0.90 / ceiling 1.10 (stable-$1 fund: catches a decimal-shift print even after it fills the window); EUTBL 150 bps (EUR/USD); CETES 300 bps (MXN/USD); SAFO not enabled (#26). **Demo:** tBENJI and tSAFO 2,500 bps, no bounds, so the Admin NAV slider (0.90–1.10) still drives margin calls while a 0.50 bad push is blocked. | A fund's NAV moves a few bps a day, so a wrong print is easy to spot: stale NAV was rejected, a wrong one was not (#6, #17). The whole window, not `prices(asset, 2)`: nav-keeper re-posts the current price every 60 s, which hides a jump from a two-record check after one re-post, and a second push next to a bad one (0.50 then 0.5001) would pass a check against only the newest different record. The off-chain keeper hold (`scripts/keeper/src/navguard.ts`, 200 bps for margin window + 60 s) is the second layer. A second independent NAV source is out of scope until an issuer publishes a signed NAV. |
| 32 | **Per-asset exposure cap (issue #29).** `AssetConfig.max_open_debt` (USDC, 7 decimals) caps the debt (principal + interest) of live repos on one collateral asset; the contract keeps `open_debt` per asset (view `open_debt(asset)`), outside `AssetConfig` so `set_asset` never resets it. `take_offer` adds the repo's debt and fails with `CapExceeded` if `open_debt + debt > max_open_debt` (exactly at the cap passes; the offer stays on the board). `repay`, `auto_repay` (also when `default` settles it) and `liquidate` subtract the whole debt, shortfall or not; a `Defaulted` repo still counts until it is liquidated. A cap of 0 = no new repos. Exits are never blocked, and a cap cut below `open_debt` leaves live repos untouched. `set_asset` rejects a negative cap (`InvalidConfig`). Cut instantly by admin or guardian, raised only behind the timelock (#33). **Launch caps** (next to the #26 haircuts): BENJI, USTBL, USDY $2M each; EUTBL $1M; CETES $0.5M; SAFO 0 (not enabled). Demo: tBENJI 100,000 USDC, tSAFO 50,000 USDC (testnet, `MAX_OPEN_DEBT` / `SAFO_MAX_OPEN_DEBT` in `scripts/deploy.sh`). | One issuer event (a pause, a NAV error, a redemption gate) can hit only a bounded slice of the book. Launch caps start small (BENJI $2M ≈ 0.5% of its $434.7M on DefiLlama, 25 Oct 2026) so the whitelisted liquidators can absorb a full default at the liquidation discount (1%, #35); raise them as liquidator depth is shown. Idea from XOXNO Lending ADR-0015; no code copied (PolyForm Noncommercial). |
| 33 | **Guardian plus timelock for risk settings (issue #27).** `Config.guardian` and `Config.timelock_secs` (> 0; demo 120 s = 2 demo days per #5, production 172,800 s = 2 days), fixed at deploy. *Tighten, instant:* `guardian_set_asset` / `guardian_set_pause` (guardian) and `set_asset` / `set_pause` (admin) apply a change only if no field adds risk: disable, raise `haircut_bps`, lower `max_open_debt` or `max_nav_age_secs`, narrow the NAV band (#31: `max_nav_move_bps` not higher; `nav_floor` added or raised, `nav_ceiling` added or lowered, neither removed), switch a pause on; same `oracle_asset`. An instant tightening drops the asset's pending proposal of the same kind (`ProposalCancelled`, `by` = who tightened), so a change queued before an emergency cannot undo it. A first listing of an asset stays instant admin: no offer can exist on an unlisted asset. Haircut changes still hit only new takes (#19). Not timelocked yet: the liquidator whitelist and a guardian rotation. Error codes follow Paused = 17 (#30), NavOutOfBand = 18 (#31), CapExceeded = 19 (#32). | A stolen admin key or a rushed change cannot add risk before lenders and borrowers can react, while the guardian can still stop trouble at once. Idea from XOXNO Lending ADR-0007; no code copied (PolyForm Noncommercial). |

| 38 | **NAV outage fallback: lender claims in kind** (NAV review side nav-outage). `liquidate` stays blocked on a stale NAV, however old (#34). | 40 | **Feed records are ledger time, one per resolution slot** (NAV review side feed-rewrite).
